# UB 内存规划重构方案：最小改动的冲突图着色替换 First-Fit

## 0. 方案定位（先读这一节）

**目标**：用确定性的冲突图着色（DSATUR + Best-Fit 槽位）替换 First-Fit 的放置决策逻辑，消除顺序敏感性。

**硬约束**：

1. **纯增量修改**：不删除任何现有代码路径，`SpecAlloc` / `outline` / 回滚全套 / 20 次重试循环全部保留为兜底；
2. **不改动其它逻辑**：liveness 分析、inplace 合并、multibuffer 展开、scope 聚合、`id2Offsets` 双核同步、写回 RewritePattern 一律不动；
3. **修改量最小**：1 个头文件加 2 个声明，1 个 cpp 文件加 ~220 行实现 + ~10 行插入调用，合计 **0 行删除**。

**核心思路一句话**：在 [PlanMemAddressOfWholeLocalBuffer](file:///home/z00498492/workspace/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/regbase/PlanMemory.cpp#L1775-L1869) 的策略梯子里，紧跟"无复用快速路径"之后插入"着色规划"，成功则直接 `continue` 进入下一个地址空间；两级着色（严格/宽松）都失败时，原封不动落入现有 First-Fit 梯子（单级 → 多级+回滚）。最坏情况 = 现状行为，零回归风险。

## 1. 现状：First-Fit 的顺序敏感性

### 1.1 First-Fit 在哪里

核心寻址在 [SpecAlloc](file:///home/z00498492/workspace/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/regbase/PlanMemory.cpp#L2080-L2144)：`outline` 是从地址 0 开始的空闲/已用区间链表，每个待放置的 `StorageEntry` 从低地址向高地址**顺序扫描**，找到第一个"跨度够大且生命期不冲突"的位置即放置，然后 [UpdateOutline](file:///home/z00498492/workspace/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/regbase/PlanMemory.cpp#L2458-L2512) 切洞、记录。First-Fit 每步只看"当前位置能不能放"，不知道后面还有谁要来、多大、和谁冲突——**放置顺序 = 分配质量**，而顺序没有被优化。

### 1.2 代码自认：两处顺序补丁

- [PlanMemoryForFuncOp](file:///home/z00498492/workspace/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/regbase/PlanMemory.cpp#L3028-L3076) 的 20 次确定性 shuffle 重试：官方承认算法靠换顺序碰运气；
- [GetReorderRootStorageEntry](file:///home/z00498492/workspace/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/regbase/PlanMemory.cpp#L1911-L1986) 手工把 DMA buffer 排前面：又一层人工排序补丁。

### 1.3 反例：同一实例，顺序不同，峰值差 67%

UB 预算 8KB，三个 buffer：A\[0,4]/4KB，B\[5,10]/4KB，C\[2,8]/2KB。冲突边：A—C、B—C（A—B 无冲突）。

```
顺序 [A,B,C]（好运）:  A@0-4, B复用0-4(生命期不交), C@4-6      峰值 6KB ✓
顺序 [C,A,B]（厄运）:  C@0-2, A@2-6(洞不够只能上推), B@6-10   峰值 10KB ✗
```

顺序二里小 C 先抢占低地址，把 A 挤上去、污染了 B 的复用机会。**着色算法从图上一眼看到 A、B 可共享，与输入顺序无关**（6.1 节演算）。

### 1.4 衍生代价

1. UB 峰值是"种子彩票"，性能回归难归因；
2. 最坏 20 × O(n²) 重复劳动；
3. 20 次失败后无法区分"实例不可行"与"算法运气差"。

## 2. 总体方案：着色优先，First-Fit 兜底

### 2.1 插入点与策略梯子

现有 [PlanMemAddressOfWholeLocalBuffer](file:///home/z00498492/workspace/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/regbase/PlanMemory.cpp#L1775-L1869) 对每个地址空间（UB/L1/L0C）依次尝试：

```
现有梯子:
  ① bufferScope2RequiredSize ≤ maxBits → 无复用顺序排布 (L1784-1790)
  ② mergedChildren 为空 → 直接 PLAN_FAILED (L1791-1794)
  ③ GetReorderRootStorageEntry 重排 → 单级规划 maxLevel (L1801-1809)   ← First-Fit
  ④ 多级规划 + 失败回滚 + splitOutline 重启 (L1810-1860)              ← First-Fit

新梯子（本方案）:
  ① 无复用快速路径（不变）
  ② 空检查（不变）
  ③ ★ 图着色·严格模式: 生命期边 + DMA pipe 边   ≈ 现有"单级 no-stall"语义
  ④ ★ 图着色·宽松模式: 仅生命期边               ≈ 现有多级降到 L0 的语义
  ⑤ 原有 First-Fit 单级 + 多级 + 回滚（原封不动，纯兜底）
```

③④ 由新增的 `PlanMemAddressByColoring` 一个方法内部完成（先严格后宽松，宽松成功时镜像现有的 pipe stall 警告）。任一着色成功 → 设置好 `bitsOffset` → `continue` 下一个空间；两级都失败 → `memscope2allocatedEntry.erase(memScope)` 后**原样落入现有 ⑤**。

### 2.3 与现有语义的精确对应

着色的两种边集刻意映射现有 SPEC_LEVEL 语义，保证"着色成功的结果"不弱于对应 First-Fit 档位的**约束强度**：

| 着色模式 | 边集 | 对应现有档位 | 含义 |
|---|---|---|---|
| 严格 | 生命期 ∩ ≠ ∅ **或** `PipeConflict` | 单级 `SPEC_LEVEL_3`（"no pipe stall plan"） | 不复用 DMA 冲突 buffer，无流水线停顿 |
| 宽松 | 生命期 ∩ ≠ ∅ | 多级降到 `SPEC_LEVEL_0` | 纯生命期复用，可能停顿（发警告） |

> 注：现有 L1（multibuffer other-slot 跨槽复用）的额外打包机会着色**不建模**，这是有意的最小化取舍——multibuffer 场景若着色峰值超标，自动落入现有 ⑤ 多级路径享受 L1 优化。见 4.1 节正确性论证。

## 3. 算法设计

### 3.1 冲突图（UDG）定义

- **节点**：`[root] + root->mergedChildren` 中每个 `StorageEntry`（multibuffer 展开后的兄弟 entry 各自是独立节点）。
- **权重**：`w(v) = AlignUp(constBits, align)`——与现有 `alignedConstBits` 完全一致。
- **边**：全部**复用现有判定函数**，零新语义：

```cpp
// 生命期冲突（内部已含 memoryUnique 特判 + cvMixIdReuseAllowedPairs 白名单短路）
bool lifeConflict = !GetOverlapBufferLife(a->bufferLifeVec, b->bufferLifeVec).empty();  // L2612
// DMA pipe 冲突（带 DenseMap 缓存）
bool dmaConflict  = strict && PipeConflict(a, b, pipeDmaConflictMap);                   // L2420
```

- **颜色 = 地址槽**：同一槽内节点两两无边（可共享地址），槽宽 = 槽内最大节点权重。目标：最小化 `峰值 = Σ 槽宽`。

### 3.2 规范化排序（消灭种子敏感性的根）

节点序来自 `mergedChildren`，而 gen 列表在循环头处被 shuffle 过（`GetLiveBuffersInLoop`），即 StorageEntryVec 顺序本身依赖 randomSeed。着色前先按**与种子无关的键**排序：

```cpp
llvm::sort(nodes, [](const StorageEntry *a, const StorageEntry *b) {
  // 先大后小（装箱大者先），再按生命期起点、终点稳定化
  auto ka = std::make_tuple(-a->bufInfo->constBits,
                            a->bufferLifeVec.front()->allocTime,
                            a->bufferLifeVec.front()->freeTime);
  auto kb = std::make_tuple(-b->bufInfo->constBits,
                            b->bufferLifeVec.front()->allocTime,
                            b->bufferLifeVec.front()->freeTime);
  return ka < kb;
});
```

此后所有决策的 tie-break 都基于该规范序 → **同一 IR 无论 seed 为何，着色输出完全一致**。这一步是让 20 次重试退化为空转的关键。

### 3.3 Sweep-Line 下界（诊断 + 剪枝）

每个节点的每段 `BufferLife` 生成两个事件：`(allocTime, +w)`、`(freeTime+1, −w)`，按 `(time, −w优先)` 排序做前缀和，最大值即下界 LB。

**正确性**：任一时刻 t 活跃的节点两两生命期相交（`lo <= hi` 闭区间语义与 `GetOverlapBufferLife` 一致），必两两异槽，权重之和逃不掉；multibuffer 兄弟生命期相同，被同时计入，与 L1 跨槽复用不矛盾（复用者与被复用者生命期不交，sweep 不会同时计入）。**LB 对所有模式（含现有 First-Fit 全档位）都是有效下界。**

**用法（保守）**：`LB > maxBits` 时跳过着色、直接落入现有 First-Fit 梯子（它会以现有方式失败并报错）——不改变任何失败路径的行为，LB 仅作为 LDBG 诊断（区分"实例不可行"与"启发式损失"）。可选的激进后续：LB 超限时直接 `failApplyBufferInfo[memScope] = LB; return PLAN_FAILED`，省掉 20 次徒劳重试（等灰度验证后再开）。

### 3.4 DSATUR 加权选择（系统化取代 shuffle）

每步从未放置节点中选：

```
priority(v) = (saturation(v), w(v), degree(v), 规范序 index)   // 逐级字典序，全取 max
saturation(v) = v 的已放置邻居所占的不同槽位数
```

- **w 大者先**：大 buffer 是稀缺资源，晚放只剩烂槽（1.3 反例的失败模式被反转）；
- **saturation 高者先**：邻居把路堵得差不多的节点自由度最小，再拖没得选（DSATUR 经典思想）。

### 3.5 Best-Fit 槽位分配（每步评估全局增量）

对当前节点 v，遍历所有现有槽 s：

- **可行**：v 与 s 内所有成员无边；
- **增量**：`Δ(s) = max(0, w(v) − s.width)`；
- **选择**：`Δ` 最小者；平手取 `s.width` 更大者（经典 Best-Fit，保住窄槽给小节点）；仍平手取槽 index 最小者。

若无任何可行槽（或——不会发生——`Δ ≥ w(v)`），开新槽（`Δ = w(v)`）。

**join 永不劣于开新槽的论证**：`Δ ≤ w(v)` 恒成立，峰值增量更小；且加宽槽只会让后续节点 join 的 `Δ` 更小或不变（`max(0, w−width)` 随 width 单调不增），槽内已有成员 offset 不变（槽起点固定）。

### 3.6 偏移生成与回填

槽按创建序做前缀和：槽 k 起点 = Σ(前 k 个槽宽)。每槽宽 = max(成员权重)，每个权重已 `AlignUp(align)` → 槽宽是 align 的倍数 → **前缀和自动满足对齐**（等价于现有逐 entry 对齐语义）。

成功后仅设置两个现有字段（`UpdateBuffer2Offsets` L1513 只读这两个字段）：

```cpp
for (slot : slots) {
  for (member : slot.members) {
    member->bitsOffset = slotStart;    // 现有字段
    RecordAllocatedEntry(member);      // 现有调试记录（L2062）
  }
  slotStart += slot.width;
}
// 所有 entry 的 alignedConstBits 已在入口处设置
```

## 4. 关键正确性论证

### 4.1 Multibuffer 兄弟节点

[ExpandMultiBufferStorageEntry](file:///home/z00498492/workspace/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/regbase/PlanMemory.cpp#L1670-L1690) 展开的 N-1 个兄弟 entry 携带与首 buffer **相同的 bufferLifeVec** → 着色图中两两冲突 → **必然分到不同槽**（不同地址），这正是 multibuffer（双缓冲/软件流水）的语义。兄弟槽还能各自与生命期不交的其它 buffer 共享，不损失安全性。

**回填兼容**：`UpdateBuffer2Offsets` 遍历 `StorageEntryVec`，每个兄弟 entry 为同一批 `inplaceBuffers` push 自己的 offset → `buffer2Offsets[buffer]` 自然累积 N 个地址（首 entry 在前、兄弟在后，与现有 L1 路径的顺序模式一致）。`firstBufferEntry2RelationOtherBufferEntry` 在着色路径恒为空 → [UpdateMultiBufferReuseExtraOffset](file:///home/z00498492/workspace/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/regbase/PlanMemory.cpp#L1526-L1543) 空转，不会重复 push。**写回链零改动。**

### 4.2 memoryUnique / CV 跨核白名单

生命期边直接复用 [GetOverlapBufferLife](file:///home/z00498492/workspace/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/regbase/PlanMemory.cpp#L2612-L2675)，其内部的 memoryUnique 短路与 `cvMixIdReuseAllowedPairs` 跨核安全判定**原样生效**，不存在重新实现引入语义漂移的可能。

### 4.3 与 First-Fit 兜底的状态隔离

- 着色只写 `bitsOffset` / `alignedConstBits` / `memscope2allocatedEntry`（调试）；
- 着色失败时 `memscope2allocatedEntry.erase(memScope)` 清掉调试记录，`bitsOffset` 残值无所谓——First-Fit 兜底路径会逐 entry 重写这些字段；
- **不调用** `GetReorderRootStorageEntry`（它有 `mergedChildren.clear()` 副作用），着色天然与顺序无关，兜底路径看到的仍是原始结构。

### 4.4 确定性

节点序 = 规范化排序（3.2），选择 tie-break = 规范序 index，槽选择 tie-break = 槽创建序。全链路无随机源 → 同一 IR 输出恒定，**与 randomSeed / 遍历顺序无关**。

### 4.5 风险与边界

| 风险 | 评估 | 缓解 |
|---|---|---|
| 着色峰值偶尔高于 First-Fit 某个幸运 seed | 理论可能（同为启发式），预期罕见 | 灰度期断言 `colored_peak ≤ first_fit_peak`（7.2）；异常 case 可经兜底路径对比定位 |
| 丢失 L1 跨槽复用打包 | multibuffer 密集的 kernel 可能峰值偏高 | 超限时自动落回 First-Fit 多级路径，可行性不受影响 |
| `PlanMemoryStrategy::LARGEST_FIRST` 对着色无效 | 着色不读该 flag | 兜底路径仍生效；后续可将 flag 映射为 tie-break 策略 |
| 大函数 O(n²) 建图 | n = 单空间 entry 数（几十~几百） | 远低于现有最坏 20×(O(n²) 规划 + 回滚)；必要时可按 allocTime 排序后只比较窗口内对 |

### 5.2 [PlanMemory.cpp](file:///home/z00498492/workspace/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/regbase/PlanMemory.cpp) 新增实现（~220 行，放在 `PlanMemAddressForSingleLevel` 之后）

```cpp
uint64_t MemPlanRegBase::ComputeColoringLowerBound(
    const SmallVectorImpl<StorageEntry *> &nodes) const {
  struct Event {
    int64_t t;
    int64_t dw;
  };
  SmallVector<Event, 64> events;
  for (const StorageEntry *e : nodes) {
    uint64_t w = e->alignedConstBits;
    for (const auto &life : e->bufferLifeVec) {
      if (life->allocTime < 0 || life->freeTime < 0)
        continue;
      events.push_back({life->allocTime, static_cast<int64_t>(w)});
      events.push_back({life->freeTime + 1, -static_cast<int64_t>(w)});
    }
  }
  // -w 优先于 +w：语义上 free@t 与 alloc@t+1 的两个节点生命期不交（闭区间）
  llvm::sort(events, [](const Event &a, const Event &b) {
    return a.t != b.t ? a.t < b.t : a.dw < b.dw;
  });
  uint64_t cur = 0, lb = 0;
  for (const Event &ev : events) {
    cur = cur + ev.dw;                  // 不会下溢：任意前缀中 -w 必有配对 +w
    lb = std::max(lb, cur);
  }
  return lb;
}

LogicalResult MemPlanRegBase::PlanMemAddressByColoring(
    StorageEntry *rootStorageEntry, size_t align, size_t maxBits) {
  // ---- Phase 0: 收集节点并规范化排序（种子无关，见设计 3.2） ----
  SmallVector<StorageEntry *, 32> nodes;
  nodes.push_back(rootStorageEntry);
  nodes.append(rootStorageEntry->mergedChildren.begin(),
               rootStorageEntry->mergedChildren.end());
  const int n = static_cast<int>(nodes.size());

  for (StorageEntry *e : nodes) {
    e->alignedConstBits =
        AlignUp(static_cast<uint64_t>(e->bufInfo->constBits), align);
    e->bitsOffset = 0;
  }
  if (n == 1) {
    // 单节点：无需着色，直接判定（等价于现有单级路径的首 entry）。
    if (nodes[0]->alignedConstBits > maxBits)
      return failure();
    nodes[0]->bitsOffset = 0;
    RecordAllocatedEntry(nodes[0]);
    return success();
  }
  llvm::sort(nodes.begin() + 1, nodes.end(),
             [](const StorageEntry *a, const StorageEntry *b) {
               auto ka = std::make_tuple(-a->bufInfo->constBits,
                                         a->bufferLifeVec.front()->allocTime,
                                         a->bufferLifeVec.front()->freeTime);
               auto kb = std::make_tuple(-b->bufInfo->constBits,
                                         b->bufferLifeVec.front()->allocTime,
                                         b->bufferLifeVec.front()->freeTime);
               return ka < kb;
             });

  // ---- Phase 1: sweep-line 下界（仅诊断 + 剪枝，不改变失败路径行为） ----
  uint64_t lb = ComputeColoringLowerBound(nodes);
  LDBG("[Coloring] lower bound = " << lb << " bits, budget = " << maxBits
                                   << " bits\n");
  if (lb > maxBits) {
    // 实例在任何生命期复用语义下都不可行；交还现有梯子按原方式失败。
    return failure();
  }

  // ---- Phase 2/3: 两级边集，严格（无 DMA 停顿）→ 宽松（纯生命期） ----
  for (bool strict : {true, false}) {
    // 建邻接表：边 = 生命期冲突 || (strict && DMA pipe 冲突)
    SmallVector<SmallVector<int>> adj(n);
    for (int i = 0; i < n; ++i) {
      for (int j = i + 1; j < n; ++j) {
        bool conflict =
            !GetOverlapBufferLife(nodes[i]->bufferLifeVec,
                                  nodes[j]->bufferLifeVec).empty() ||
            (strict && PipeConflict(nodes[i], nodes[j], pipeDmaConflictMap));
        if (conflict) {
          adj[i].push_back(j);
          adj[j].push_back(i);
        }
      }
    }

    // DSATUR + Best-Fit 槽位
    struct ColorSlot {
      uint64_t width = 0;
      SmallVector<int, 4> members;
    };
    SmallVector<ColorSlot, 16> slots;
    SmallVector<int, 32> slotOf(n, -1);
    SmallVector<bool, 32> placed(n, false);
    SmallVector<int, 32> satDeg(n, 0);

    auto recomputeSat = [&](int v) {
      DenseSet<int> used;
      for (int u : adj[v])
        if (slotOf[u] != -1)
          used.insert(slotOf[u]);
      satDeg[v] = static_cast<int>(used.size());
    };

    for (int step = 0; step < n; ++step) {
      // 选择：max(saturation, weight, degree)，规范序 index 兜底平手
      int v = -1;
      for (int i = 0; i < n; ++i) {
        if (placed[i])
          continue;
        if (v == -1)
          { v = i; continue; }
        auto key = [&](int x) {
          return std::make_tuple(satDeg[x], nodes[x]->alignedConstBits,
                                 adj[x].size());
        };
        if (key(i) > key(v))
          v = i;
      }

      // Best-Fit：可行槽中选 Δpeak 最小者
      int bestSlot = -1;
      uint64_t bestDelta = 0, bestWidth = 0;
      for (int s = 0; s < static_cast<int>(slots.size()); ++s) {
        bool feasible = llvm::all_of(slots[s].members, [&](int m) {
          return !llvm::is_contained(adj[v], m);
        });
        if (!feasible)
          continue;
        uint64_t delta = nodes[v]->alignedConstBits > slots[s].width
                             ? nodes[v]->alignedConstBits - slots[s].width
                             : 0;
        if (bestSlot == -1 || delta < bestDelta ||
            (delta == bestDelta && slots[s].width > bestWidth)) {
          bestSlot = s;
          bestDelta = delta;
          bestWidth = slots[s].width;
        }
      }
      if (bestSlot == -1) {
        slots.emplace_back();
        bestSlot = static_cast<int>(slots.size()) - 1;
      }
      slots[bestSlot].width =
          std::max(slots[bestSlot].width, nodes[v]->alignedConstBits);
      slots[bestSlot].members.push_back(v);
      slotOf[v] = bestSlot;
      placed[v] = true;
      for (int u : adj[v])
        if (!placed[u])
          recomputeSat(u);
    }

    // ---- Phase 4: 偏移前缀和 + 峰值判定 ----
    uint64_t peak = 0;
    for (const ColorSlot &s : slots)
      peak += s.width;
    LDBG("[Coloring] strict=" << strict << " peak = " << peak << " bits\n");
    if (peak > maxBits)
      continue; // 换宽松边集重试

    uint64_t off = 0;
    for (const ColorSlot &s : slots) {
      for (int m : s.members) {
        nodes[m]->bitsOffset = off;
        RecordAllocatedEntry(nodes[m]);
        LDBG("[Coloring] entry @" << off << " width " << s.width << "\n");
      }
      off += s.width;
    }
    if (!strict) {
      // 镜像现有 L1862-1865 的停顿警告语义
      llvm::WithColor::warning(llvm::outs())
          << "[hivm-plan-memory] There reused some dma buffers in "
          << rootStorageEntry->bufInfo->bufferScope
          << " address space, which may stall pipe. Coloring plan needs "
          << peak << " bits while " << maxBits << " bits available!\n";
    }
    return success();
  }
  return failure(); // 两级都失败，落入现有 First-Fit 兜底
}
```

## 6. 演算示例

### 6.1 第一章反例的消解（A/B/C，边 A—C、B—C）

```
Phase 1 下界: t=0:+4(A)→4; t=2:+2(C)→6; t=4:-4(A); t=5:+4(B)→6; ...
             LB = 6KB ≤ 8KB → 可行

着色（规范序: A,B 同为 4KB 取生命期早者 A 在前; 初始 saturation 全 0）:
  Step0  key: A=(0,4K,1) B=(0,4K,1) C=(0,2K,2) → A/B 平手取规范序 A
         → 无槽可 join → 开 S1(w=4)；更新 C 的 sat=1
  Step1  key: B=(0,4K,1) C=(1,2K,2) → C 的 saturation 更高 → 先放 C
         → S1 内有邻居 A 不可进 → 开 S2(w=2)；更新 B 的 sat=1
  Step2  B → 槽评估: S1={A} 无边, Δ=max(0,4−4)=0 → join S1（峰值零增长）
  偏移: S1@0(4KB)={A,B}, S2@4(2KB)={C} → 峰值 6KB = LB，最优
```

任何输入顺序经规范排序后演算完全一致。对照 First-Fit 顺序二的 10KB：**消除 67% 峰值差**。

### 6.2 链图：五个 buffer 展示 DSATUR + Δpeak 细节

P\[0,3]/3K，Q\[2,6]/2K，R\[4,9]/3K，S\[7,12]/2K，T\[10,14]/3K；边构成链 P—Q—R—S—T。LB = 5KB（任意相邻对同时活跃）。

```
规范序(按大小): P,R,T (3K, 按生命期) → Q,S (2K)
Step0  key: P=(0,3,1) R=(0,3,2) T=(0,3,1) → R 度最高 → 开 S1(w=3)
       更新: Q,S 的 sat=1 (邻居 R 在 S1)
Step1  key: Q=(1,2,2) S=(1,2,2) P=(0,3,1) T=(0,3,1) → Q/S 平手取规范序 Q
       → S1 内有邻居 R 不可进 → 开 S2(w=2)；更新 P 的 sat=1
Step2  key: P=(1,3,1) S=(1,2,2) T=(0,3,1) → P 的 w 更大 → 先放 P
       → S1 可行(P—R 无边), Δ=max(0,3−3)=0 → join S1
Step3  key: S=(1,2,2) T=(0,3,1) → S 的 sat 更高 → S1 内有邻居 R 不可进
       → S2 可行(Q—S 无边), Δ=0 → join S2
Step4  T → S1 可行(P/T,R/T 无边), Δ=0 → join S1
偏移: S1@0(3K)={R,P,T}, S2@3(2K)={Q,S} → 峰值 5KB = LB
```

**对照组**：First-Fit 按输入序 \[P,Q,R,S,T] 逐点判冲突 → 全部线性堆叠，峰值 13KB（差 2.6 倍）。着色从图上一眼看到 {P,R,T} 两两不交可叠进同一槽。

| 回归风险 | — | 兜底全保留，最坏 = 现状 |
