# SSBUF CV 异构调度机制与执行顺序

## 1. 总体机制

SSBUF 调度将原始循环中的计算划分为 CUBE 块和 VECTOR 块。AIC、AIV 根据输入数据是否就绪、输出 buffer 是否有空位，决定是否下发对应计算块。

- **核间 buffer 固定为 2 槽**：生产者、消费者按各自执行次数 `% 2` 选择槽位。
- **VECTOR 核内跨块 buffer 固定为 3 槽**：按对应计算块执行次数 `% 3` 选择槽位。
- 每个计算块有独立的执行计数器。只有其 `scf.if` 条件成立、实际执行该块时，计数器才加 1；外层 for 的轮次不等于原始数据迭代号。
- 核间队列状态放在 SSBUF；核内队列状态由循环携带的标量保存。读要求已生产数量 `> 0`，写要求未消费数量 `< 槽位数`；生产后加 1，消费后减 1。多个输入、输出要求同时满足。
- 条件还可以包含启动限制、总迭代数限制，不能只看 buffer 的空满。

### PIPE_S 与数据同步

循环体通过核间 `<PIPE_S>, <PIPE_S>` 同步交替获得调度权，保护 SSBUF 状态的读写。每次获得调度权后，按 IR 顺序检查该核的各个 `scf.if`，条件不满足的块跳过。

这描述的是标量侧的调度、下发顺序。**PIPE_S 交接不表示前面下发的计算全部完成**；CUBE、VECTOR 的硬件计算流水可以重叠。数据真正可读、buffer 真正可重写，由 FIX、V、MTE 等流水线之间的 wait/set 保证。SSBUF 中的计数不能直接当作硬件计算完成次数。

for、while 都应按循环体的条件、状态更新和退出条件分析；不能仅凭循环类型推断调度。本例是 for，下面的启动轮数和 `N+2` 上界仅针对本例。

### 计算块和 buffer

| 核 | 调度循环中的计算块 | 功能 | 执行计数器 |
|---|---|---|---|
| AIC | 第一个 scf.if：C1 | QK matmul | `%arg29` |
| AIC | 第二个 scf.if：C2 | PV matmul | `%arg30` |
| AIV | 第一个 scf.if：V1 | mask、softmax，产生 C2 输入及 V2 所需的中间结果 | `%arg32` |
| AIV | 第二个 scf.if：V2 | 更新循环累加结果 | `%arg33` |

每组数据的依赖为 `C1[k] → V1[k] → C2[k] → V2[k]`，另外还有 `V1[k] → V2[k]` 的核内依赖。`k` 从 0 开始，表示计算块处理的逻辑数据组序号。两个 AIV 分别处理各自切分后的数据。

| 生产者 → 消费者 | buffer | 槽数 |
|---|---|---:|
| C1 → V1 | AIV UB `%alloc_7 / %alloc_8` | 2 |
| V1 → C2 | AIC L1 `%alloc_6 / %alloc_7`，AIV 中有对应镜像 | 2 |
| C2 → V2 | AIV UB `%alloc_9 / %alloc_10` | 2 |
| V1 → V2 | AIV `%alloc_11/12/13`、`%alloc_14/15/16`，两组中间结果 | 每组 3 |

SSBUF 地址 `0/1024` 对应两个 AIV 的 C1→V1 队列，`4/1028` 对应 C2→V2，`8/1032` 对应 V1→C2。AIC 检查两个 AIV 对应的状态，AIV 使用自身 sub-block 对应的状态。

### 条件如何决定启动顺序

设每个计算块需要执行 N 次，初始执行次数及队列计数均为 0：

- **C1**：两个 AIV 的输出队列均未满，且 C1 尚未执行 N 次。
- **C2**：两个 AIV 提供的输入均就绪、输出队列均未满、C2 尚未执行 N 次，并且 **本轮开始时的 C1 执行次数 ≥ 2，或者 C1 已执行完 N 次**。
- **V1**：C1 输入就绪，发往 C2 的队列未满，两组核内三槽队列均未满，且 V1 尚未执行 N 次。
- **V2**：C2 输入就绪，两组 V1 核内结果均就绪，且 V2 尚未执行 N 次。

关键细节：C2 的启动条件使用循环携带的旧 `%arg29`，没有使用同轮 C1 返回的新 `%79`。因此第二轮即使已经下发 `C1[1]`，检查时旧计数仍为 1，C2 仍不启动。V2 则使用 V1 返回的更新后核内计数 `%118#1 / %118#2`。

### 前几轮的实际下发顺序

以 N=4 为例，本例两个调度循环均执行 `N+2=6` 轮。每轮先由 AIC 检查 C1、C2，再由 AIV 检查 V1、V2：

| for 轮次 | AIC 下发顺序 | AIV 下发顺序 |
|---|---|---|
| 1 | `C1[0]` | `V1[0]` |
| 2 | `C1[1]` | `V1[1]` |
| 3 | `C1[2] → C2[0]` | `V1[2] → V2[0]` |
| 4 | `C1[3] → C2[1]` | `V1[3] → V2[1]` |
| 5 | `C2[2]` | `V2[2]` |
| 6 | `C2[3]` | `V2[3]` |

VECTOR 三槽的作用：前两轮 V1 留下第 0、1 组结果；第三轮先执行 `V1[2]`，此时需要第三个槽，随后 `V2[0]` 消费第 0 组结果并释放槽位。此后按 `% 3` 周转。

若 N 更大，第五轮可继续下发 `C1[4] → C2[2]`、`V1[4] → V2[2]`，直到进入排空阶段。

本用例最前面的 query tile 只有 N=1，此时 C2 通过“C1 已全部执行完”条件提前启动：

| for 轮次 | AIC | AIV |
|---|---|---|
| 1 | `C1[0]` | `V1[0]` |
| 2 | `C2[0]` | `V2[0]` |
| 3 | 无计算块 | 无计算块 |
