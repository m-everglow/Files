# V1内部分块：首版编译验证

**本文件记录v1的编译结果。后续硬件验证发现行映射问题，已在v2修正并通过精度；详见同目录《V1分块硬件验证.md》。性能尚未验证。**

## 本次修改

- 从原始全双槽ttadapter出发，不使用此前的单槽adapter。
- 保留V1前半部分的mask、缩放和行最大值计算。
- 将V1后半部分的exp、bf16转换、行求和、NZ转换和写L1放入行分块循环。
- 切分前128行按16行为一块。通过tensor.extract_slice读取相应行，行求和通过tensor.insert_slice汇集回完整状态。
- 每块写入现有L1双槽的对应位置；等待L1槽空闲放在分块循环前，完整结果就绪的set放在循环后。外层SSBUF计数仍按整个V1更新一次。
- 首版使用单小块周转，尚未设计内部小块双缓冲重叠。

## 编译检查

| 项目 | 结果 |
|---|---|
| bishengir-opt输入解析 | 通过 |
| bishengir-compile完整编译 | 返回码0，生成v1_row16_serial.o（50,824 B） |
| C1→V1 UB槽 | 保留两个64 KiB槽 |
| C2→V2 UB槽 | 保留两个32 KiB槽 |
| V1输出临时UB | 原32.5 KiB，现8.5 KiB |
| 最终HIVM静态UB指针最高末端 | 248,576 B = 242.75 KiB，容量248 KiB |
| 硬件、参考精度、性能 | 未验证 |

最终小块分配为memref<16x17x16x1xbf16, ub>，含padding占8.5 KiB；切分后的相关VF接口包含8行输出。实际分配比此前估算更大，不能直接按逻辑元素数计算UB。

静态地址统计来自最终保存的HIVM，不是完整动态生命期峰值分析。编译成功说明本次PlanMemory已接受分配；仍需硬件核对分行索引、两个AIV的区间及同步。

## 剩余问题

编译器警告：使用了DMA buffer地址复用，可能导致流水等待；若不复用这些DMA buffer，需求为2,455,552 bits，即299.75 KiB。因此保留两个逻辑槽不代表完全保留原来的硬件重叠，性能还需要实测。

本次没有修改编译器源码或安装的compiler.py，没有替换.o，也没有修改后续NPU-IR。
