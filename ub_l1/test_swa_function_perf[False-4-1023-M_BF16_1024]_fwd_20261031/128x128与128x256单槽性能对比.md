# SWA forward：128×128 与 128×256 单槽性能对比

**结论：128×256 单槽方案功能、精度通过，本次未看到性能提升。两项耗时均值略高，但绝对差值小于 2 µs，按既有规则归为波动。**

| 指标（三轮均值） | 128×128 原始流程 | 128×256 C2→V2 单槽 | 变化 | 结论 |
|---|---:|---:|---:|---|
| forward 端到端 | 84.908 µs | 86.820 µs | +1.911 µs（+2.25%） | 波动，无提升 |
| _swa_fwd_kernel | 25.108 µs | 26.697 µs | +1.589 µs（+6.33%） | 波动，无提升 |

## 测试口径

- 输入：test_swa_function_fwd_perf[False-4-1023-M_BF16_1024]，两边固定 multibuffer=False。
- 128×128：原始 Triton 端到端流程，不替换 adapter。
- 128×256：在 linalg_to_bin_enable_npu_compile_910_95 写入 ttadapter_path 后，仅替换 forward adapter；C2→V2 核间槽数2→1，其他通道不变；后续 NPU-IR 正常编译。
- 同一物理卡5，各三轮；顺序为 baseline1、singlePV1、singlePV2、baseline2、baseline3、singlePV3。每轮独立进程、日志、cache，固定配置。
- 六次 pytest 均通过，均使用同一输入与仓库 torch 参考后端执行 assert_close。
- 端到端：预热后，记录完整 forward 调用及同步完成的30次墙钟耗时，每轮取均值；包含 Python 下发和同步开销，单轮间有波动。
- kernel：profiler 的 op_statistic.csv / Avg Time(us)，每轮20次采样，不含 backward。两种计时口径分开比较。
- TRITON_ALWAYS_COMPILE、TRITON_DEBUG、TRITON_PRINT_AUTOTUNING 为1；性能采集关闭 LLVM 全量打印。
- 三轮候选实际编译输入均核对与替换 adapter SHA256 一致；实验后 compiler.py 已恢复。
