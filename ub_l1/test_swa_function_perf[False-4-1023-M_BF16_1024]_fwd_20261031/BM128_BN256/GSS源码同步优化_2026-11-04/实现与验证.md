# GSS 源码同步优化

已实现并完成编译、UT、硬件精度与 kernel 耗时验证。本轮未采集流水。

## 修改

位置：/home/m00953828/AscendNPU-IR/bishengir/lib/Dialect/HIVM/Transforms/GraphSyncSolver/GraphSyncSolver.cpp

GSS 对同一 scf.for 内两个动态 ssbuffer.if 复用同一块私有 L1 的形态，改为：

- 实际 matmul 读完 L1 后发完成信号。
- 下次覆盖这块 L1 前，等待上次实际读取的完成信号。
- 空轮次携带状态，不收发信号；循环退出时消费剩余信号。

不写死 kernel 名称、buffer 地址或 tiling。当前处理两个分支的 scf.for；其他结构保持原来的 GSS 逻辑。地址重叠关系、宏内部事件占用、MTE2 通道还有其他用途时不接管。没有增加支配关系或 IR 合法性检查。

PASS 选项 enable-conditional-buffer-sync 默认开启。bishengir-opt 可通过：

    --hivm-graph-sync-solver="enable-conditional-buffer-sync=false"

关闭本优化。该选项是 GSS PASS 选项。

QK/P 的 L1 双槽、K/V 复用布局、所有 buffer 地址和访存保持不变；本次只调整 AIC 同步，AIV 代码不变。
