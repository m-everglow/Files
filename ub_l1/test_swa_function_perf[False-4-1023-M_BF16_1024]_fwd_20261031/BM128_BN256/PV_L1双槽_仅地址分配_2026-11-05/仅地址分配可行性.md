# 只改UB地址：独立FP32输出是否放得下

**结论：保持现有VF、访存顺序、同步、调度和槽数，要求FP32输出使用不与其他buffer重叠的32 KiB时，没有248 KiB以内的地址分配解。** 这不是说原PV L1版无法运行；原版通过输出复用才能放下。

## 容量怎么来的

仅取6块大buffer，先完全不计mask及全部小buffer：

| 原PlanMemory输出中的AIV SSA | buffer | 大小 |
|---|---|---:|
| %73 | QK槽0 | 64 KiB |
| %74 | QK槽1 | 64 KiB |
| %75 | PV单槽 | 32 KiB |
| %83 / %151 | acc初值和循环更新值，同址，只计一份 | 32 KiB |
| %178 | VF1输出P，含padding | 32.5 KiB |
| %120 | 要求独立的FP32输出 | 32 KiB |
| 合计 | | **256.5 KiB** |

按原VF1每条读取、写入检查，P和当前QK的安全相对起点只能是：P起点至少早30208 B，或者晚65536 B。因此局部最多重叠3072 B分配空间，其中实际P数据3008 B。

对上述6块buffer重新全局排地址。为了让问题比真实kernel更容易，还允许P使用上述局部重叠，不检查另一QK槽的跨核所有权；其余大buffer保持下面列出的必要冲突关系。256 B对齐时，最小总范围为 **259584 B = 253.5 KiB**，超过248 KiB **5.5 KiB**。把容量限制为248 KiB，求解器返回不可行。

这里已经不计mask、小buffer，并放宽了跨核限制。因此重新安排这些小buffer，无法填平这5.5 KiB缺口。253.5 KiB是放宽条件后的下界，不是一张可上硬件的分配表。

## 为什么其他大buffer不能直接合并

| 组合 | 原IR中的冲突 |
|---|---|
| QK槽0 / QK槽1 | 反向flag按槽独立归还；一个由V1读取时，另一个允许C1生产，不能合成同址 |
| QK / acc | acc跨迭代保留，C1生产QK会覆盖后续V2仍要读的acc |
| PV / acc | V2逐段同时读取两份不同输入，PV写入不能覆盖旧acc |
| P / acc | V1写P时，旧acc仍需留给后面的V2 |
| PV / QK | VF1读取当前QK时，PV可已由AIC写好，等待随后的V2 |
| P / PV | VF1写P时，PV可已就绪但尚未由V2读取 |
| P / QK | 只允许上面算出的有限部分重叠；不能整块原地复用 |

原34 μs流水有直接例子（同一core、未归一化时间，单位μs）：
- PV写入：39.300–39.484；随后读取它的V2：40.522–40.724。
- 期间VF1：39.999–40.486，读取QK槽0并写P。PV和P/QK槽0在这里有冲突。
- PV下一组写入：58.666–58.855；V2：59.921–60.116。
- 期间VF1：59.396–59.885，读取QK槽1并写P。另一个QK槽同样不能固定拿来与PV合并。

这些读取/写入关系由现有VF和同步决定，不是PlanMemory当前保守区间的假设。

## 为什么128×128能独立放输出

128×128的QK每槽32 KiB，两槽共64 KiB；128×256每槽64 KiB，两槽共128 KiB。P也由16.25 KiB增到32.5 KiB。PV移到L1让UB的PV由双槽64 KiB变为单槽32 KiB，但没有抵消前两项增长。因此不能直接照搬128×128的独立输出布局。
