# L1 ND单槽、UB单槽验证

结论：kernel均值 38.3757 μs，已进入30多μs。三轮精度均通过。

| 配置 | kernel均值 μs |
|---|---:|
| 128×128基线（此前） | 25.0594 |
| 128×256 L1 ND双槽、UB单槽 | 41.1682 |
| 128×256 L1 ND单槽、UB单槽 | 38.3757 |

同一二进制三轮：38.4435、38.3109、38.3728 μs。每轮20个kernel profiling样本，共60个。相比41.1682 μs，耗时下降 6.78%。

## 核内同步和地址复用

分析代码：
- GraphSyncSolver/MemInfo.cpp：PointerLikeInfo::checkConflict按地址范围判断冲突。
- GraphSyncSolver/Utility.cpp：getAddresses将字节地址转换为bit，与buffer位数一致。没有发现地址单位或相邻范围判断错误。
- 41μs版本的AIC中，K、V输入都分配在L1地址0x68000。因此需要MTE1读取完成后，MTE2才能覆盖这个地址；此类WAR同步不能直接删除。

当前C1与L1→UB已经合并，进入C1要求两个AIV的UB逻辑空闲。C1结果紧跟着复制到UB，原有第二个L1暂存槽未体现并行收益。改为单槽后，腾出128 KiB；PlanMemory自然把K、V分开：
- K：0x48000，64 KiB。
- V：0x58000，64 KiB。

因此跨K/V的真实同址复用依赖消失，核内同步依赖也随分配改变。本实验没有删除或手工挪动同步指令，也没有修改GraphSyncSolver代码。
这说明问题与内存分配产生的同步约束有关；尚不能断言同步pass本身有错误。
本次同时减少了L1槽和改变K/V分配，收益不能全部归于某一条同步。

## 消融与精度

先测试“L1单槽+K/V mem_unique”，再测试“仅L1单槽”。两者最终二进制完全一致，说明mem_unique标记并非必需。
仅L1单槽额外一轮：38.4721 μs，精度通过。发布的实验IR采用无mem_unique标记的简单版本。

三轮最大绝对误差0.015625，平均绝对误差0.000292448385，与Torch参考对比通过。
实际执行二进制SHA256：48cb4674446d02e7dc2fc6b9ad31bd97950590b2543a74f8ac2d7e4d4bf2e20b。

关闭enable-preload候选精度通过，但二进制与41μs原版一致，不能视作有效的预取变换消融或优化。
