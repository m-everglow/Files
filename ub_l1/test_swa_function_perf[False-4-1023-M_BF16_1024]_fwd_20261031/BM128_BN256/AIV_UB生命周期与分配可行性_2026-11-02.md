## 4. 不同阶段的存活

| 阶段 | 必须保留 | 可回收或复用 |
|---|---|---|
| 启动两轮 | QK、V1 产生的 L1 数据和两组小向量 | 尚未产生的 PV 没有有效内容，但不能据此忽略后面流水执行时的冲突 |
| V1 / VF0 | 当前 QK、mask、循环携带值；其他槽可能并行生产 | mask 在 VF0 完成后可复用 |
| V1 / VF1 | 未读完的当前 QK、逐步产生的 %alloc_39、循环携带值、其他跨核数据 | 已读 QK 前缀能否覆盖，要逐字节检查 |
| V1→L1 复制 | %alloc_39 保留到 MTE3 读完，L1 槽保留到 C2 消费 | VF1 完成不等于 %alloc_39 可覆盖 |
| V2 | 当前 PV、旧 %arg31、选中的两组小向量 | %alloc_33 可覆盖旧 %arg31；PV 读完才释放 |
| 尾部 | 最终三个 loop result，以及三个待 store 输出 | 已完成使用的跨核区、三槽区可用于输出 |

if 不执行时，旧 loop-carried value 继续存活，不能在 then-region 末尾截断。

第三轮先执行 V1[2]，随后才执行 V2[0]：此时三组小向量均有待消费内容，这里确实需要保留三组结果。

## 5. 256 KiB 和 253.0625 KiB 是怎么算的

先把 VF1 附近的几块大 buffer 相加：

| buffer | 大小 |
|---|---:|
| 两个 QK buffer：%alloc_7、%alloc_8 | 128 KiB |
| 两个 PV buffer：%alloc_9、%alloc_10 | 64 KiB |
| 累加结果：%arg31，可与 %alloc_17 / %alloc_33 同址，只计一份 | 32 KiB |
| VF1 输出：%alloc_39 的有效数据，暂不计 padding | 32 KiB |
| 合计 | **256 KiB** |

**256 KiB 只是上面几项相加，还没有扣除 QK 与 VF 输出可能共享的空间。** 它也没有计小 buffer，以及 %alloc_39 的 0.5 KiB padding。

为什么两份 QK、两份 PV 都要计入：

- AIV 下发 V1[2]、V2[0] 后，可以交还 PIPE_S。此时不代表这两个计算已经完成。
- V1[2] 还在执行、V2[0] 还没读 PV[0] 时，AIC 可能已经产生 QK[3]、PV[1]。
- 所以，另一槽可能已有尚未使用的数据，不能直接覆盖。旧的 %arg31 也要留给后面的 V2。

再检查：**VF1 能否把输出写到已经读完的 QK 空间里？**

当前 VF1 按行读 f32，但按 NZ 布局写 bf16。如果输入输出使用同一个起始地址，第一段只读完输入 [0,256)，就会写到 [2080,2112)，覆盖后面尚未读取的输入。

检查其他起始地址后，最多能共享 **3008 B**。再多就会覆盖尚未读取的数据。具体计算见 verify_vf1_overlap.py。

因此：

**256 KiB − 3008 B ÷ 1024 = 253.0625 KiB。**

这仍超过每 AIV 的 248 KiB。这里已经忽略小 buffer 和 padding，而且还没有增加跨核同步带来的其他限制。

**这个数只针对当前 VF 的读写顺序和现有同步，不是 PlanMemory 实际分配的结果。修改 VF 后，需要重新计算。**

## 6. 允许补同步时：163.5 KiB 候选布局

保留逻辑双槽、三槽和 VF 计算，通过新增跨槽依赖，让同组两个跨核槽不再同时保留不同内容。地址区间为 [起点,终点)，单位 B。

| 地址区间 | SSA |
|---|---|
| [0,65536) | %alloc_7、%alloc_8 |
| [65536,98304) | %alloc_9、%alloc_10 |
| [98304,131072) | %alloc_17、%alloc_33 |
| [131072,164352) | %alloc_34、%alloc_39 |
| [164352,164608) | %alloc |
| [164608,164864) | %alloc_0 |
| [164864,165120) | %alloc_18、%alloc_37 |
| [165120,165376) | %alloc_19、%alloc_32 |
| [165376,165632) | %alloc_35、%alloc_36 |
| [165632,165888) | %alloc_38 |
| [165888,167424) | %alloc_11～%alloc_16，每个独占 256 B |

尾部 %alloc_26 放地址 0，%alloc_27 放 65536，%alloc_28 与最终累加结果同址放 98304。两份不同格式输出不会互相覆盖。

最高地址 **167424 B = 163.5 KiB**。需要补齐：

- QK 跨槽：任何下一次 C1 FIX 写共享区前，等待上一次 V1 读/改完成；两个 AIV 都要完成。
- PV 跨槽：任何下一次 C2 FIX 写共享区前，等待上一次 V2 读取完成；覆盖两个 AIV。
- mask/P 本地共享：下一轮 GM→UB mask load 前，等上一轮 UB→L1 P 复制读完；VF0 读完 mask 后，VF1 才能写 P。
- 跨槽依赖使用独立同步令牌并正确初始化、收尾；不能对已有 flag 简单多 wait 一次。

原逐槽 flag 不能替代新增跨槽依赖。候选会减少 C1/V1、C2/V2 的双槽流水重叠，可能降速。

**这是容量与同步设计，尚未修改 adapter、编译或上卡。它说明允许调整同步时存在候选，不代表原 IR 仅换地址就能用这张表。**
