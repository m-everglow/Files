# 128×256：L1 中转实验

原始 IR：PlanMemory 需要 UB 273.25 KiB，超过 248 KiB。

改写：AIC 的 fixpipe 先将结果写入交替使用的两个 L1 槽；等待单个 UB 槽空闲后，用 l12ub 搬到 UB。AIV 消费完成后释放同一同步标志。两个 64 KiB 的 UB 结果槽合为一个；L1 新增两个 128 KiB 槽。改写后的输入见 `before_planmemory_l1_single_ub_serialized.mlir`。

| 验证 | 结果 |
|---|---|
| IR verifier、PlanMemory pass | 通过 |
| 完整 bishengir-compile | 通过；生成主对象及 AIC/AIV 对象 |
| Triton 对象替换 | 通过；缓存的 npubin 与预编译 .o 的 SHA-256 相同 |
| NPU 输出正确性 | 未确认：128×256 调用 90 秒超时 |

未改的 128×128 基线在 1、5 号卡也超时；基础 torch.npu 运算在 1、3、5 号卡未能正常完成。本轮没有可比较的输出，不能把超时归因于改写后的同步。

对照 IR 仅合并两个 UB 槽、不经过 L1，PlanMemory 同样通过。因此容量收益来自减少 UB 槽；L1 中转是否能保留 CUBE 与 VECTOR 的重叠，需要在设备恢复后用输出和性能验证。

注意：新增 L1 后，before PlanMemory 不复用 L1 静态总量为 544 KiB，高于 512 KiB；PlanMemory 通过复用完成分配，并提示 DMA buffer 复用可能造成流水停顿。原始日志、实验脚本、.o 与对照 IR 位于 `/home/m00953828/mojo/ub_l1/swa_tiling_debug_archive_20261031/BM128_BN256`。
