# QK：L1 双槽、UB 单槽——编译验证

**编译和单次 forward 精度验证均通过。性能尚未验证。**

## 改动

- tiling 保持 128×256，f32 数据类型不变。
- C1 将结果写入两个 L1 槽，每槽 128 KiB，包含两个 AIV 各自的 64 行。
- 新增 AIC 搬运块，由 SSBUF 的数据数量和 UB 空闲状态控制；L1 有数据、两个 AIV 的 UB 工作区都可用时，分别搬运 64 行。
- 每个 AIV 只保留一个 64 KiB UB 工作区；V1 使用完成后释放。
- SSBUF 原地址 0/1024 记录 L1 队列，新地址 12/1036 记录 UB 工作区状态。PIPE_S 保护计数读写；MTE1/V flag 保证搬运完成和允许覆盖。
- 循环暂用 N+4 次调度轮次，留出收尾轮次；性能阶段再检查能否减少。
- V1 的原有完整输出复制保留。

## 编译后的内存

从最后一次 PlanMemory 输出的 pointer_cast 地址和 buffer 大小计算，AIC/AIV 的镜像不重复计数。

| 内存 | 已分配地址范围 | 容量 | 剩余 |
|---|---:|---:|---:|
| 每 AIV 的 UB | 227.25 KiB | 248 KiB | 20.75 KiB |
| 每 AIC 的 L1 | 480 KiB | 512 KiB | 32 KiB |

UB 中只保留一份 64 KiB 工作 buffer。VF0 的输入和对应输出使用同一 buffer，没有再增加一个 64 KiB 临时结果。

L1 不复用时是 544 KiB；两个不同 C1/C2 分支中的 64 KiB 加载 buffer 最终同址，降到 480 KiB。编译器提示 DMA buffer 复用可能增加等待，性能需要单独实测。

## NPU-IR 分支与支持

分支：qk-l1-ssbuf-staging  
基础 commit：a0d796eb7ab6c49390d12df869f0a484439f02fe  
当前改动尚未提交。

1. l12ub 增加 sub_block_idx=1 的实验支持，调用单独的 AIV1 模板；默认 AIV0 路径不变。两份源切片都是 16×4×16×16 f32，目标都是 64×256 f32，避免完整 128 行写入半大小 UB。
2. VFOperandSubstitution 增加显式标记 hivm.vf_inplace_source，允许本实验的静态工作区作为原地输出；保留 VF 函数内读写安全、其他源使用、输出使用跨越释放同步等检查。标记约定：调用方允许覆盖输入，并在下一次消费前重新填入新数据。
3. 新标记正例、未标记反例，以及原有 VF 替换测试均通过：3 个 lit 测试文件 PASS。

这不是仅修改 bcmlir 就能直接用原后端完成的版本，需要配套本分支的上述支持。目前 AIV1 专用模板用于本用例的 4D→2D f32 搬运。

L1→UB API 的 AIC 执行和目标 AIV 参数，见 [CANN asc_copy_l12ub 文档](https://asc.gitcode.com/api/SIMD-API/c_api/cube_datamove/cube_compute_store/asc_copy_l12ub.html)。
